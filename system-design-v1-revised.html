RESUMATE · REVISED V1 · SENIOR-REVIEWED

Defer complexity, not capability.

The V1 architecture keeps the modular monolith and core safety boundaries, while removing job/worker/OCR infrastructure until product evidence proves it necessary.

01 / Senior review outcome

The product model survives review. The runtime becomes deliberately smaller.

APPROVED

V1 product scope

The current product scope remains valid.

ADOPTED FOR V1

Direct LLM extraction

Multimodal extraction replaces the prior parser → OCR → mapping runtime.

DEFERRED

Job/worker infrastructure

ProcessingJob, workers, polling, queues, and OCR remain future-ready but are not V1 requirements.

V1 should contain the minimum architecture necessary to build the product clearly, correctly, securely, and maintainably.

02 / Resume / Variant model

Terminology is simpler; independent snapshots and lineage are unchanged.

Resume / Variant lineage

RESUMERoot, independently persisted document. `ROOT` remains implementation-only.
→
VARIANT A1`rootResumeId = Resume A`
`sourceResumeId = Resume A`
→
VARIANT A2`rootResumeId = Resume A`
`sourceResumeId = Variant A1`

One entity shape

`kind: ROOT | VARIANT`, ownership, root/source lineage, revision, JSONB content, and timestamps can share the same Resume entity/table.

One non-negotiable rule

Every Variant belongs to exactly one root Resume. Resume and Variant snapshots are independent; updating one never mutates another.

Direct Edit updates the current persisted Resume/Variant. Copy & Edit uses temporary Working State, then saves a Variant. Root deletion may transactionally promote the oldest preserved Variant to root Resume.
Local editor state is protected by a debounced server-backed Working Draft and a Resume revision number. expectedRevision prevents stale writes; a multi-device conflict must be surfaced for resolution rather than silently overwriting newer work.

04 / Multimodal LLM extraction

Extraction determines what the document says. It never improves the Resume.

Direct extraction and review flow

UPLOADValidate PDF, DOCX, JPG, JPEG, PNG
STOREPrivate object storage
EXTRACTDocumentExtractionService
VALIDATESchema + evidence + quality
REVIEWUser corrects uncertainty
SAVEResume JSON or original file
SERVICE BOUNDARY

DocumentExtractionService

Initial adapter: OpenAIDocumentExtractor. Future implementations can include PaddleOCRExtractor, ManagedOCRExtractor, or HybridExtractor without changing product rules.

HARD BOUNDARY

Extraction is not enhancement

Do not rewrite descriptions, improve grammar, infer achievements, add metrics, fabricate skills/dates, or silently omit regional fields during extraction.

Missing data is safer than fabricated data.
Quality Initial threshold Required action
High ~80%+ Show extracted Resume, require review, allow save/import.
Partial ~50–79% Flag uncertainty, request correction, allow save only after user review.
Unusable < ~50% Do not fake success; request clearer input or offer Form/Chat.
LLM extraction contract
Extract only visible or strongly supported information. Use `null` or review markers where facts are unreadable. Preserve unknown meaningful sections as Custom Sections, preserve regional/personal fields, deduplicate repeated headers/footers only when clear, avoid merging unrelated columns, and preserve source/page metadata when feasible.

05 / Revised AI harness

Structured output is necessary, but it is not automatically truthful.

AI Harness

User / file inputRelevant task input only
→
Task Router + Context BuilderDedicated task contract and token/output budget
→
Provider Adapter + modelStructured output → schema → evidence/business validation → result

DOCUMENT_EXTRACTION

Field accuracy, omissions, hallucination, layout, multilingual handling, latency, and cost determine routing.

Other task classes

SMALL_REWRITE, RESUME_ENHANCEMENT, FULL_TAILORING, ATS_ANALYSIS, and EDITOR_COMMAND use task-specific contracts.

Routing rule

Use the cheapest model that reliably meets the extraction quality requirement.

Application state remains the source of truth. Model memory is never trusted as product memory. AI changes are structured, validated, and user-reviewed before persistence.
AI TRUTH BOUNDARY

User-supported facts remain the limit

AI may transform, organize, clarify, and professionally express user-supported facts, but must not fabricate unsupported career evidence.

QUALITY DECISION

Confidence is evidence, not truth

Extraction quality must not rely only on a model's self-reported confidence score. It combines coverage, readability, consistency, uncertainty, and structural checks before review.

06 / Security and direct-request failure handling

LLM extraction makes privacy minimization and server-side control more important, not less.

Extraction privacy

Send only the uploaded Resume required for extraction; never attach unrelated account data, other Resumes, or cross-user extracted content.

Provider boundary

Keep provider usage behind the server. Never expose provider keys to the client. Log operational metadata, not raw Resume content.

Validation first

Validate extension, MIME, file signature, size, and ownership before sending a document to the provider; preserve private object storage.

FAILURE FLOW

Limited retry, then clear alternatives

Transient external failures receive limited retry + backoff + jitter. Extraction offers Retry, clearer upload, Form, or Chat; enhancement can continue manually; PDF can retry export.

TIMEOUTS

Operation-specific classes

Normal API, small AI request, document extraction, full tailoring, and PDF rendering use separate timeouts. Exact values are benchmark decisions.

Platform access control

Authentication, authorization, and ownership checks apply to every Resume, Variant, file, draft, and action. Resume data is Private-by-default.

Data classification

Sensitive, private, and public data are handled differently. Private-file access uses short-lived signed URLs rather than public object links.

Public Profile boundary

Visibility settings create a published snapshot for anonymous public HTML; a Public Profile never reads mutable private Resume data directly.

Storage and derived artifacts: Use-As-Is original Resume file remains durable while the Resume exists. Extract & Edit source upload uses limited retention by default and a user may delete it earlier; future paid plans may extend retention without hard-coding the core domain around one plan. Generated PDFs are short-lived unless explicitly preserved; temporary or abandoned files expire. Resume structured JSON → renderer → headless browser → PDF. PDF is a derived artifact, never the Resume source of truth.

07 / Direct-request scaling and capacity

Protect the simpler runtime until evidence calls for a durable job system.

Measured evolution path

MeasureLatency, traffic, provider limits, cost
→
Indexes + DB tuning + cachingBounded connection pools
→
AI rate/concurrency controlHorizontal app scaling before job architecture

Direct-request capacity controls

Account rate limits, AI quotas, bounded concurrent AI operations, provider timeout handling, retry limits, request cancellation where practical, and request admission control.

Overload UX

Use 429 / Retry-After where appropriate, or a 503/high-demand state: High demand. Please try again shortly. Persistent queued-waiting UX is deferred.

Initial assumptions remain: 100–500 registered users, 25 concurrent baseline, and 100 concurrent success scenario. Test direct AI latency, simultaneous extraction/tailoring, PDF load, provider limits, and DB connections.

08 / Revised cost model

Removing OCR compute reduces infrastructure complexity; extraction becomes an AI cost.

INFRASTRUCTURE TARGET

~$50/month

Without worker/OCR runtime, V1 may stay nearer the lower end. Web, PostgreSQL, R2, PDF load, backups, and traffic still determine actual cost.

INFRASTRUCTURE REVIEW

~$100/month

Architecture-review ceiling, not an automatic shutdown rule.

AI GUARDRAILS

~$100/month · ~$150/month · ~$250/month

Target, warning, and emergency-review monthly AI thresholds. DOCUMENT_EXTRACTION belongs in telemetry.

Required telemetry: taskType, model, input tokens / image usage, cached input, output tokens, latency, cost, success/failure, and retry count.

10 / Deferred evolution

The V1 omission list is deliberate and has explicit future triggers.

DEFERRED

ProcessingJob + worker

Reconsider when operations outlive requests, fail on restart, require durable retries/history, or need priority coordination.

DEFERRED

PaddleOCR / dedicated OCR

Deferred to avoid CPU/GPU runtime and deployment complexity, reduce small-team operational burden, and validate the product first. Reconsider if extraction cost, scan volume, accuracy, privacy requirements, multilingual quality, or throughput make it worthwhile.

DEFERRED

Durable queue / Redis/BullMQ

Reconsider for persistent backlog, multi-worker coordination, difficult retry scheduling, priority work, or strict delivery guarantees.

V1Single Modular Monolith
Direct AI extraction and operations
PHASE 2Dedicated worker for measured heavy operations
PHASE 3ProcessingJob + durable queue for proven backlog/retry complexity
PHASE 4OCR or hybrid extraction pipeline for pressure on accuracy/cost
PHASE 5Selective component separation only when organizational scale justifies it
