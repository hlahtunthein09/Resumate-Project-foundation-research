ResuMate
Product Workflow
& User Actions.

A high-level view of how a user creates, imports, reviews, saves, improves, tailors, manages, and exports a Resume—before technical architecture is designed.

01 — Core product idea

ResuMate turns Resume work into a controlled user journey, not an AI black box.

Users can create from scratch, use guided AI/chat, or upload an existing Resume. They review content and AI changes before a Resume becomes saved truth.

Create

Form or AI/chat

Users can choose structured form entry or a conversational flow without needing design-tool knowledge or professional English writing.

Import

Use As-Is or rebuild

An existing PDF, DOCX, or image can be used directly or extracted into structured ResuMate content for review and rebuilding.

Manage

Save, improve, tailor

Saved Resumes can be edited, enhanced, analyzed, tailored, exported, shared, set Active, duplicated, or deleted according to user choice.

Source: Product Workflow Draft §§1–2.

03 — Saved Resume lifecycle

Saving creates a Version; controlled branch-and-save creates a Variation.

CREATE / IMPORTTemporary Working State
PREVIEWUser reviews content
SAVEVersion
EDIT / COPYUpdate Current or create working copy
REVIEWPreview selected changes
SAVE BRANCHVariation
Direct Edit

Update the current Resume

A normal edit works on the existing persisted Resume and does not automatically create a new Version.

Create Copy & Edit

Save a new Variation

A temporary working copy can be edited and saved as a Variation under the same root Version group.

Duplicate Version creates a new independent root Resume. Save as Variation creates a branch inside the original Version group.

Source: Product Workflow Draft §§3–4, §13–14; Domain Model v1 §§4–6.

04 — AI enhancement & job tailoring

AI analysis produces suggestions; the user decides what becomes permanent.

Supported evidence

  • AI may clarify, summarize, reorder, and improve professional wording.
  • Relevant evidence can be emphasized for a job context.
  • ATS/quality analysis can provide explainable diagnostics and recommendations.

Missing or unsupported evidence

  • Show a gap or ask for clarification.
  • Do not invent skills, employers, dates, certifications, metrics, projects, or achievements.
  • Do not silently make AI output permanent.
SELECTEnhance, Analyze, or Tailor
ANALYZEResume + optional Job Context
SUGGESTWriting, emphasis, structure, diagnostics
REVIEWAccept, edit, or reject
PREVIEWSee proposed result
SAVEUpdate Current or Save Variation

Source: Product Workflow Draft §§5, 7, 15; Domain Model v1 §10.

05 — Job Context

Tailoring accepts any useful combination of job information; it never forces one input order.

Direction

Target Role(s)

A broader role or role set used to orient a Resume.

Opportunity

Applied Position

A specific position the user plans to pursue, distinct from Target Role.

Details

JD, requirements & context

Job description, requirements, company, location, and employment type can be supplied in any combination.

If a job description has no explicit role title, AI may infer likely context, but the user can confirm or edit it. Automatic application submission and full Job/Application records remain out of this workflow draft.

Source: Product Workflow Draft §6; Domain Model v1 §15.

06 — Upload and extraction

Extraction makes imported content reviewable; it does not replace user judgment.

Step User-facing behavior Safety boundary
Upload User supplies PDF, DOCX, JPG, or PNG Resume. Upload is not yet a persisted Version.
Extract Parser/AI creates structured Resume values where possible. Low-confidence fields are flagged rather than guessed.
Review User corrects extracted data and chooses a ResuMate Template. Meaningful unknown sections are retained, not silently discarded.
Save User previews and saves the intended result as a Version. Only the explicit save/import action creates persisted identity.

Source: Product Workflow Draft §10; Domain Model v1 §§11–14.

07 — Template, content & preview

Template changes presentation only; preview must predict export.

Content preservation

Never silently delete Resume data

Personal details, education, experience, skills, photo, and contextual regional fields remain part of the Resume snapshot even when a template lacks a suitable presentation slot.

Predictable output

Editor → Preview → Export

Editing, previewing, and exporting should follow the same content and presentation rules. The user should not see one result in the editor and a conflicting result after export.

Changing Template does not create a Version or Variation and does not alter factual Resume content. ResuMate should warn or recommend a compatible template rather than silently removing meaningful content.

Source: Product Workflow Draft §§8–9, §15.3; Domain Model v1 §§16–17.

08 — Active CV

One saved Version or Variation can be selected as the user’s Active CV—optionally.

Selection

0..1 Active CV

A personal user can set one saved Version or Variation as Active. Resume-building remains available with none selected.

Future context

Job seeking & Portfolio

The selection gives future job-seeking and public-context features a clear professional direction without exposing the private User Profile.

No forced change

User remains in control

Newer relevant evidence may trigger a recommendation. ResuMate never auto-updates, auto-switches, or merges Active CV data.

Deleting the Active Resume clears the selection. The system must not automatically activate another Resume.

Source: Product Workflow Draft §11; Domain Model v1 §7.

09 — Saved Resume action map

Every persisted Version or Variation exposes clear, separate user actions.

EDITDirect Edit or Create Copy & Edit
IMPROVEAI Enhance, ATS / Quality Analysis, Tailor to Job
PRESENTPreview, Change Template, Export / Download, Share
MANAGESet as Active CV or Delete; root Versions can Duplicate Version

Delete always requires confirmation. Deleting a Variation removes it; deleting a root Version can remove the whole group or preserve Variations by promoting the oldest Variation to the new root Version.

Source: Product Workflow Draft §§12–14; Domain Model v1 §19.

10 — MVP workflow boundary

This draft locks the user/product flow without adding technical architecture or future platform scope.

Included in workflow review

  • Create, import, review, preview, save
  • Version / Variation behavior
  • Enhance, analyze, tailor, and user approval
  • Template, localization, export, share
  • Active CV and safe delete behavior

Explicitly future scope

  • Portfolio system
  • Job Platform integration and auto-apply
  • Application lifecycle tracking
  • Agency multi-client workflow
  • Custom Template Builder
  • Trash / restore, revision history, bulk import

Source: Product Workflow Draft §17.

11 — Senior review

The draft is intended to test product clarity before technical components are mapped.

Journey clarity

Can a non-technical reviewer follow it?

  • Are Create, Import, Enhance, Analyze, Tailor, and Export clearly separated?
  • Is Use As-Is necessary in MVP?
  • Are any steps too complex for a beginner user?
Domain clarity

Do key rules remain understandable?

  • Is Version vs Variation clear?
  • Is Direct Edit vs Create Copy & Edit intuitive?
  • Are user approval, Job Context, Active CV, templates, and delete behavior appropriate?

Source: Product Workflow Draft §18.
